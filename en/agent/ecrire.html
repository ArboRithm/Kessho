Write to the memory ​

This journey brings a fact, a principle, a goal, a person or a document into the memory: the agent creates a note (an "atom") in the right zone. For what the session itself leaves, see Archive a session.

What you ask the agent ​

You ask your agent

« Note this down: "A sealed fragment is never edited by hand." »

→ The agent callsmem_note
  • title = Sealed fragment
  • content = A sealed fragment is never edited by hand.
You ask your agent

« Remember this principle, a red line: only document what the code supports. »

→ The agent callsmem_principle
  • title = Only document what the code supports
  • content = A claim that neither the catalog nor the code supports does not belong in the reference.
  • force = red-line
You ask your agent

« Add a short-term goal: publish the documentation by 2026-12-01. »

→ The agent callsmem_goal
  • title = Publish the documentation
  • horizon = short
  • deadline = 2026-12-01
You ask your agent

« Create a card for Claire Martin, a client. »

→ The agent callsmem_person
  • name = Claire Martin
  • relation = client
You ask your agent

« Absorb this document into the memory: /Users/ben/Documents/cahier-des-charges.pdf. »

→ The agent callsmem_doc
  • path = /Users/ben/Documents/cahier-des-charges.pdf
  • title = Cahier des charges
You ask your agent

« Set this aside, I'll sort it later: remember to ask for a quote for the LED rail. »

→ The agent callsmem
  • content = Remember to ask for a quote for the LED rail.
  • hint = idea

When you do not say what kind of content it is ("note this", "keep that"), the agent may use mem, which drops it in the inbox; when you do ("remember this principle"), it calls the tool of that type.

What the agent does ​

Each tool writes a new note:

ToolWhere it landsRequiredGood to know
mem00-inbox/contenthint steers the later filing: note, principle, goal, person or idea.
mem_note20-knowledge/title, contenttitle serves as the name.
mem_principle40-principles/{scope}/title, contentforce: red-line, heuristic (default), value or action-rule.
mem_goal50-goals/{horizon}/titlehorizon: short (default), medium or long; status: open (default), in-progress, done or abandoned; deadline as YYYY-MM-DD.
mem_person60-people/{relation}/namerelation: colleague (default), client, friend, family or other. The card is marked sensitive by default (sensitive).
mem_doc00-inbox/path (absolute)One local document per call: Markdown, text, PDF, DOCX, XLSX, PPTX, HTML or CSV.

All except mem accept project (the project it belongs to) and scope: work (default), personal or all.

None of these writes overwrites an existing note. If the name is already taken, the server picks another by adding a suffix (-2, -3…); the answer gives the path actually written. The agent therefore does not have to check first whether the note exists. When the write lands in a cross-cutting zone, that zone's index.md is regenerated.

Other tools write notes, with their own rule:

  • mem_archive, in full mode, creates the notes of derive; a name already taken makes it refuse the whole archive (see Archive a session).
  • mem_codebase records in a project's map a fact that the code does not say by itself (fact, body, project). It asks for the files the fact describes (describes, paths relative to the repository, which must exist) or, failing that, unmeasurable_because, the reason it attaches to no file; with neither, the write is refused. The catalog advises consulting mem_codebase_scan first.

Correcting an existing note is not the job of these tools: renaming, moving, attaching or removing is done with those of Maintain the memory.

What you see ​

The written note appears in its zone, here Knowledge (20-knowledge): one row per note, with its type and its project (see Zones). The freshness indicator lights up as soon as the agent writes, and Reload refreshes the list. To open the note and read or edit it, see Atom and editor.

You can also create a note yourself, with New in the zone header: the agent is not needed.
