Avec un agent ​

Un agent branché sur Kessho est un assistant IA (Claude Code, Codex, Gemini CLI… voir Connecter l'agent) qui parle à votre mémoire par le serveur MCP de Kessho. Il y lit ce que vous avez déjà décidé, y écrit ce que la session apporte, et vous le retrouvez à l'écran : l'application et l'agent regardent le même dossier de notes (voir Choisir sa mémoire).

Pourquoi ​

Un assistant n'a pas de mémoire d'une session à l'autre, ni d'un outil à l'autre. Avec Kessho, ce qui compte est écrit dans votre mémoire, un dossier de notes Markdown à vous : la session suivante, dans le même assistant ou dans un autre, repart de là sans que vous ayez à tout redire.

Le cycle : reprendre, travailler, archiver ​

  1. Reprendre. Vous dites « on reprend le projet X » ; l'agent charge le contexte de ce projet. Voir Reprendre un projet.
  2. Travailler. Pendant la session, l'agent peut chercher, noter une décision, ranger. Voir Chercher dans la mémoire et Écrire dans la mémoire.
  3. Archiver. En fin de session, l'agent écrit une archive datée et met à jour le contexte du projet. Voir Archiver une session.

Qui fait quoi ​

Ce que faitOù cela se voit
L'application (Kessho)Déclare son serveur chez vos assistants, dépose les procédures qui leur disent quand l'appeler, affiche la mémoire, la synchronise en un clic.Les écrans du guide de l'application.

Chaque page de cette section part de ce que vous dites à l'agent, puis explique ce que fait l'agent (les outils appelés, ce qui change dans la mémoire), puis ce que montre l'application.

Les sept parcours ​

  • Connecter l'agent : brancher votre assistant, et vérifier qu'il voit Kessho.
  • Reprendre un projet : retrouver où vous en étiez, sans rien re-expliquer.
  • Archiver une session : garder la trace d'une session, et l'annuler si besoin.
  • Chercher dans la mémoire : retrouver une décision, un fichier, une note.
  • Écrire dans la mémoire : noter un fait, un principe, un objectif, une personne, un document.
  • Entretenir la mémoire : contrôler la santé du dossier, renommer, déplacer, retirer.
  • Synchroniser la mémoire : garder la mémoire à jour entre vos postes, avec git.

La liste complète des outils, avec leurs paramètres, est dans la Référence MCP.

Un agent ne fait pas tout seul ​

Certains outils ne s'exécutent qu'à une condition, que chaque parcours rappelle : un essai à blanc avant d'appliquer (apply, confirm), une confirmation motivée pour retirer une note. Ces garde-fous sont ceux du serveur, pas une politesse de l'agent.

Une autre sorte de consigne n'est pas vérifiée par le serveur : pour mem_git_commit et mem_git_resolve, c'est la description de l'outil qui demande à l'agent l'accord de l'utilisateur ; le serveur, lui, ne le contrôle pas.
